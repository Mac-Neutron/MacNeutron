# libkrun for the EAC microVM

The microVM host links libkrun (Apache-2.0, github.com/containers/libkrun) at the `main` commit in `PIN`, plus the
patches here; the fork's `macneutron` branch (github.com/Mac-Neutron/libkrun) carries the same commits. Stable releases
come later. `build.sh` builds it into `build/eac-vm-work/libkrun/` with the `ffi` feature, which exports main's v2 C API
(device manager, payload, VMM builder). Make a new patch in `build/eac-vm-work/libkrun-src` (branch `macneutron`), then
`git format-patch --no-signature -o patches <pin>..macneutron`.

Patches:
- 0001: boot EFI zboot kernels (Fedora's vmlinuz has a zstd payload; the PE loader only scanned for gzip).
- 0002: free the guest's reported pages for real on macOS: unmap the range from the VM, MADV_FREE, map it back
  (madvise alone frees nothing while the VM maps a page a vCPU wrote).
- 0003: set Apple's EnTSO (ACTLR_EL1 bit 1) on every vCPU, so the whole guest runs with x86 (TSO) memory ordering.
- 0004: stop the VM (abort) if a reported range cannot be mapped back; warn once if Hypervisor.framework refuses an unmap.
- 0005: the virtio-gpu device on a dxmt context instead of rutabaga_gfx (milestone 4a, the Metal transport). rutabaga_gfx
  needs virglrenderer and keeps its component traits private, so `src/rutabaga_dxmt`, patched in for it, implements
  the API subset the device uses: capset 24 (under 32: the guest driver's capset mask is `1 << id` on an int), HOST3D blobs as 16 KiB-aligned host memory, and command buffers and fences
  handed to the callbacks the VM host registers (`mn_dxmt_set_ops`, `mn_dxmt_fence_done`). A blob the guest frees is
  handed to the executor, which unmaps it once nothing (a Metal buffer, a running op) uses it. The macOS blob map refuses
  an offset off a host page, and `krun_gpu_device_without_display` makes a device without scanouts or virgl capsets, so the device offers one capset. `include/libkrun.h`
  is generated by `make gen-libkrun-bindings`, whose tool isn't installed here: its two lines for that constructor were
  added by hand from `target/ffier-krun.json`.
- 0006: start the vmm worker thread on macOS. The v2 builder starts it only for SEV, TDX or an x86 split irqchip,
  but on macOS it maps gpu blobs (and virtiofs DAX windows) into the guest; without it the first blob map panics.
