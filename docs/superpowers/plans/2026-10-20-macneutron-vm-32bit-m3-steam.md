# 32-bit games in the VM, M3: Steam for 32-bit games — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 32-bit game's lsteamclient calls (WoW64 Unix calls) reach Mac Steam through the forwarder, run by Valve's own
WoW64 functions in the Mac `lsteamclient.so`.

**Architecture:** The guest forwarder registers `__wine_unix_call_wow64_funcs`: each entry sends the call's 32-bit
params (`wow64_<call>_params`, descriptors generated by `gen.py` with 4-byte pointers) with the wire index's high bit
set. `mn-steam-host` copies the pointees into a region below 4 GiB, puts their 32-bit addresses in the params and calls
`___wine_unix_call_wow64_funcs[index]`. The low region needs `com.apple.developer.cross-architecture-support`, which
the kernel honours only for an executable in a bundle with the provisioning profile: `mn-steam-host` becomes
`mn-steam-host.app`. `steamclient_get_unix_buffer` (lsteamclient's 32-bit copy of a returned string, whose source is
the guest's own kept copy) runs in the guest.

**Tech Stack:** C11 (forwarder, host), Python 3 (gen.py), Swift (macneutron-vm, VMToolsInstaller tests), POSIX sh,
the builder and the microVM.

**Spec:** `docs/superpowers/specs/2026-10-20-macneutron-vm-32bit-games-design.md` §6.

## Global Constraints

- No gate per milestone (maintainer, 2026-10-20): development runs only; the final gates run after M4 (spec §8).
- The spike passed (2026-10-20): an executable signed with the cross-architecture entitlement, application identifier
  `49QMZXLR8S.net.authspot.macneutron.wine`, team `49QMZXLR8S`, inside a bundle with
  `$MACNEUTRON_PROVISIONING_PROFILE` as `Contents/embedded.provisionprofile`, maps `MAP_FIXED` at `0x10000000`; the same
  binary outside a bundle is killed (exit 137). The fallback of spec §6 is not needed.
- Never start or quit Steam (maintainer). A development run that needs Mac Steam uses it only if it is already running.
- Valve binaries are never committed.
- The 64-bit path's behaviour and table stay as they are; the checksum changes (both sides ship together).

## Review Focus

- A 32-bit call whose pointee the host copies must see a 32-bit address that is valid in the host: every host copy of
  an `MN_PTR32` field, count pointer and inner pointer comes from the low region (marshal-test, wow64 cases).
- A returned string reaches 32-bit code through `steamclient_get_unix_buffer` copying from the guest's kept copy, never
  through the host (guest wow64 script's persona name row).
- Concurrent 32-bit callers get separate low slices; a 33rd concurrent one gets an error, not memory shared with another
  thread (`ponytail:` ceiling in host.c).
- A host without the entitlement (an unsigned development build) still serves 64-bit calls and answers 32-bit ones with
  an error (host start-up line).
- A guest with no host answers WoW64 init and CreateInterface as the 64-bit path does (offline-test).

### Task 1: 4-byte pointers and the low region in the marshaller

**Files:**
- Modify: `eac-vm/steam-forward/marshal.h` (flag, arena fields), `eac-vm/steam-forward/marshal.c`
- Test: `eac-vm/steam-forward/tests/marshal-test.c`

**Interfaces:**
- Produces: `MN_PTR32 = 8` (field flag: the field's pointer, its count pointer and its inner pointer are 4 bytes,
  zero-extended); `struct mn_arena` gains `uint8_t *low; size_t low_used, low_cap;` — `mn_unpack_request` takes every
  `MN_PTR32` pointee copy (and its count-pointer prefix and inner copy) from `low` (16-byte aligned, zeroed), failing
  with `MN_E_NOMEM` when `low` is NULL or full; `mn_arena_free` resets `low_used`. The params copy itself stays a heap
  allocation.

- [ ] **Step 1: Write the failing tests** in `marshal-test.c`, run only when a low mapping succeeds (`mmap` of 2 MiB at
  `0x10000000`, `MAP_FIXED_NOREPLACE` on Linux; otherwise print `wow64 cases skipped: no memory below 4 GiB`): a
  hand-written descriptor over a packed struct `{ uint32_t str; uint32_t buf; uint32_t n; uint32_t out; }` with fields
  `MN_STR_IN|MN_IN_ONLY|MN_PTR32`, `MN_BUF|MN_PTR32` (count `n`, width 4) and `MN_FIXED|MN_PTR32` (8 bytes), guest
  pointees in the first MiB, host `low` in the second:
  - `wow64 round trip`: pack, unpack with `low`; every host pointer field is below 4 GiB, inside `low`, and its bytes
    equal the guest's; the host writes the out field; reply packs and unpacks; the guest's 4-byte pointers are unchanged
    and its out pointee holds the host's bytes.
  - `wow64 without low`: unpack with `low = NULL` returns `MN_E_NOMEM`.
  - `wow64 low full`: `low_cap` smaller than the buffer returns `MN_E_NOMEM`; `mn_arena_free` then lets the same
    request unpack.
- [ ] **Step 2: Run them where low memory exists** — `sh eac-vm/builder.sh sync eac-vm/steam-forward mn-steam-forward
  && sh eac-vm/builder.sh ssh 'cd mn-steam-forward && make -s marshal-test OUT=$HOME/mn-sf-test'`. Expected: build
  fails on `MN_PTR32` / `low`. Also `make -s marshal-test` on the Mac: the old cases still pass (after Step 3) and the
  wow64 ones print skipped.
- [ ] **Step 3: Implement** — `get_ptr`/`set_ptr` take the field's width; `ptr_count`, inner pointers and the reply's
  pointer restore use it; `arena_alloc` gains a `low` choice.
- [ ] **Step 4: Run Step 2's commands.** Expected: builder `marshal-test: ok` with the three wow64 rows passing (ASan/UBSan
  clean); Mac all old rows pass, wow64 skipped.
- [ ] **Step 5: Commit** — `git commit -m "steam-forward: 4-byte pointers (MN_PTR32) and the host's low region in the marshaller"`

### Task 2: WoW64 descriptors and the guest's WoW64 table

**Files:**
- Modify: `eac-vm/steam-forward/gen.py`, `eac-vm/steam-forward/client.h`, `eac-vm/steam-forward/client.c`,
  `eac-vm/steam-forward/wire.h`, `eac-vm/steam-forward/tests/gen-check.py`, `eac-vm/steam-forward/tests/offline-test.c`

**Interfaces:**
- Consumes: Task 1's `MN_PTR32`.
- Produces: `extern const struct mn_call_desc mn_calls_wow64[];` (same length and order as `mn_calls`, from
  `wow64_<call>_params`; `steamclient_init_registry` keeps its no-params entry); `#define MN_WOW64 0x80000000u` (wire
  index bit); `uint32_t mn_client_call_wow64(uint32_t index, void *params);`; `uint32_t mn_tables_checksum(void);`
  (both tables: `mn_table_checksum(mn_calls, n)` continued over `mn_calls_wow64`), used by both handshakes;
  `NTSTATUS mn_wow64_get_unix_buffer(void *params);` in client.c (memcpy of `buf.len` bytes from `buf.ptr` to the
  4-byte `ptr`, `STATUS_SUCCESS`; `ptr` 0 or `buf.ptr` 0: `MN_STATUS_INVALID_PARAMETER`).

gen.py rules for the WoW64 table: a field `W32_PTR(decl, name, type)` is parsed as `decl` with `MN_PTR32` added to its
flags; a pointee size is `sizeof(<pointee type from decl>)`, not `sizeof(*access)` (in C a `W32_PTR` field is an opaque
`struct ptr32`); OVERRIDES apply with `struct <call>_params` → `struct wow64_<call>_params` and `w_CallbackMsg_t` →
`w32_CallbackMsg_t`; `steamclient_get_unix_buffer`'s WoW64 entry is `MN_UNSUPPORTED` (the guest answers it). The guest
table's WoW64 entries call `mn_client_call_wow64(idx, p)`, except that one, which is `mn_wow64_get_unix_buffer`.
`report.txt` gains the WoW64 counts.

- [ ] **Step 1: Write the failing tests** — offline-test: replace the "refused" row with: WoW64 `steamclient_init`
  (params `{ .g_tmppath.value = 0 }`) answers 0 with no host; WoW64 `steamclient_CreateInterface` sets `_ret.handle` to
  0; `mn_calls_wow64[i].params_size == sizeof(struct wow64_steamclient_init_params)` for init and every field there has
  `MN_PTR32`; `mn_wow64_get_unix_buffer` copies 6 bytes from a 64-bit source into a 4-byte destination (a local buffer
  whose address fits 32 bits is not available on the Mac: run that row only where `mmap` below 4 GiB works, as Task 1).
  gen-check.py: also checks the WoW64 arrays.
- [ ] **Step 2: Run** — `make -s offline-test gen-check` (Mac). Expected: compile/link FAIL (`mn_calls_wow64`
  undefined).
- [ ] **Step 3: Implement** gen.py's WoW64 pass, client.c's `mn_client_call_wow64` (the 64-bit call's body shared
  through a static helper taking the descriptor and the wire index; `no_steam` casts by table) and
  `mn_wow64_get_unix_buffer`, and `mn_tables_checksum`.
- [ ] **Step 4: Run** — `make -s offline-test gen-check marshal-test` (Mac). Expected: `offline-test: ok`, gen-check
  passes, report line printed with the WoW64 unsupported count (record it in the commit message).
- [ ] **Step 5: Commit** — `git commit -m "steam-forward: WoW64 descriptors and the guest's WoW64 table; 32-bit returned strings copied in the guest"`

### Task 3: mn-steam-host runs WoW64 calls in a low region

**Files:**
- Modify: `eac-vm/steam-forward/host.c`

**Interfaces:**
- Consumes: Task 1's arena `low`, Task 2's `MN_WOW64`, `mn_calls_wow64`, `mn_tables_checksum`.

- [ ] **Step 1: Implement.** At start-up: `dlsym(h, "__wine_unix_call_wow64_funcs")`; map the low region
  `MAP_FIXED` at `0x20000000`, 1 MiB for the WoW64 init's path buffer plus 32 slots of `MN_MAX_MESSAGE + (4 << 20)`;
  print `mn-steam-host: 32-bit calls: ready` or `mn-steam-host: 32-bit calls: unavailable (<why>)`. A connection takes
  a slot (mutex-guarded bitmap) at its first WoW64 request and returns it when it closes; no slot, no low region or no
  WoW64 table: the call is answered `MN_STATUS_NOT_IMPLEMENTED` without running. The handshake uses
  `mn_tables_checksum()`. A request with `MN_WOW64` unpacks against `mn_calls_wow64` and runs `wow64_funcs[index]`;
  WoW64 `steamclient_init` gets the low path buffer's 32-bit address in `g_tmppath`. `ponytail:` comment on the 32-slot
  ceiling.
- [ ] **Step 2: Build** — `make -s host` (Mac). Expected: exit 0; running the unsigned binary with a temp socket and
  `--client-dir` of an empty folder exits 3 as before (no Steam touched).
- [ ] **Step 3: Commit** — `git commit -m "mn-steam-host: WoW64 calls through Valve's WoW64 functions, in a low region per connection"`
